# InfraBot

Telegram-бот для управления домашней (корпоративной) инфраструктурой на базе .NET 8.  
Позволяет удалённо выполнять PowerShell-скрипты на серверах Windows через WinRM, управлять доступом пользователей и отслеживать результаты запусков.

---

## Тема

**Создание бота для управления домашней инфраструктурой**

---

## Цели проекта

- Разработать Telegram-бота для централизованного управления серверами в домене Active Directory.
- Реализовать ролевую модель доступа с разграничением прав между пользователями.
- Обеспечить удалённый запуск PowerShell-скриптов на серверах через WinRM с учётной записью службы (sAMAccountName).
- Хранить конфигурацию (пользователи, серверы, скрипты, связи, задачи) в файловом хранилище JSON с возможностью перехода на PostgreSQL (LinqToDB).
- Организовать многошаговые сценарии (диалоги) для CRUD-операций через Telegram.
- Предоставить операторам и администраторам отчёты о выполненных задачах в формате запрос–ответ.

---

## Описание

InfraBot — курсовой проект, в котором Telegram выступает единой точкой входа для администрирования инфраструктуры.

**Основные сущности:**

| Сущность | Назначение |
|---|---|
| `BotUser` | Пользователь Telegram с ролью и списком доступных связок «сервер + скрипты» |
| `Server` | Сервер Windows (FQDN, порт WinRM, учётная запись службы) |
| `Script` | PowerShell-скрипт с настройками (таймаут, подтверждение, возврат JSON) |
| `ServerScripts` | Связка сервера и списка разрешённых скриптов для пользователя |
| `SvcSamAccount` | Учётные данные доменной службы для WinRM-подключения |
| `JobRun` | Запуск скрипта на сервере (статус, результат, код выхода) |

**Архитектура:**

```
TelegramBot/          — клиент Telegram, обработка Update
Scenarios/            — многошаговые диалоги (создание сервера, скрипта, запуск задачи и т.д.)
Core/
  Entities/           — модель данных
  Enums/              — роли и статусы задач
  Interface/          — контракты репозиториев и сервисов
Infrastracture/
  Repository/Files/   — JSON-хранилище (один объект на строку / один объект в файле)
  Repository/DB/      — LinqToDB + PostgreSQL (заготовка)
Data/                 — тестовые данные и конфигурация
```

**Хранение данных:**

- коллекции в одном файле — JSON Lines (`bot_users.json`, `svcSamAccounts.json`);
- объекты в отдельных файлах — папки `Data/Scripts/`, `Data/ServerScripts/`, `Data/Jobs/` (`{id}.json`).

## Роли пользователей

| Роль | Описание | Права |
|---|---|---|
| **Guest** | Новый пользователь после `/start` | Регистрация, просмотр справки |
| **Pending** | Ожидает одобрения администратором | Ограниченный доступ до назначения роли |
| **Blocked** | Заблокирован администратором | Доступ к функциям бота запрещён |
| **Operator** | Оператор инфраструктуры | Просмотр доступных серверов, запуск разрешённых скриптов, просмотр отчётов по своим задачам |
| **Admin** | Администратор | Полный доступ: пользователи, серверы, скрипты, учётные записи службы, связки доступа, назначение ролей |

## Базовые функции

Взаимодействие с ботом строится в формате **запрос → ответ** (команды и многошаговые сценарии).

### Команды (запрос–ответ)

| Команда | Описание | Роли |
|---|---|---|
| `/start` | Регистрация пользователя в системе | Guest, Pending, Admin |
| `/help` | Список доступных команд для текущей роли | Все (кроме Blocked) |
| `/info` | Информация о пользователе и его доступах | Operator, Admin |
| `/report` | Отчёт по выполненным задачам (JobRun) | Operator, Admin |
| `/serverslist` | Список доступных серверов | Operator, Admin |
| `/addserver` | Добавление нового сервера (запуск сценария) | Admin |
| `/cancel` | Отмена текущего сценария | Все активные сценарии |

### Сценарии (многошаговый диалог)

| Сценарий | Действие | Роли |
|---|---|---|
| Создание / изменение / удаление сервера | CRUD серверов, настройка WinRM | Admin |
| Создание / изменение / удаление скрипта | CRUD PowerShell-скриптов | Admin |
| Создание / изменение / удаление учётной записи службы | CRUD `SvcSamAccount` | Admin |
| Создание / изменение / удаление связки доступа | Привязка сервера и скриптов к пользователю | Admin |
| Запуск задачи (`JobRun`) | Выбор сервера → скрипта → подтверждение → выполнение через WinRM | Operator, Admin |

### Пример диалога (запуск скрипта)

```
Пользователь:  /serverslist
Бот:           Доступные серверы:
               1. web-01 (web01.domain.local)
               2. db-01  (db01.domain.local)

Пользователь:  /run web-01 Get-DiskInfo
Бот:           Запустить скрипт «Get-DiskInfo» на сервере web-01? [Да / Нет]

Пользователь:  Да
Бот:           Задача поставлена в очередь (Id: b2000001-...).
               Статус: Running...

Бот:           ✅ Задача завершена.
               Результат (JSON):
               {"drives":[{"name":"C:","freeGb":120.5}]}
```

## Технологии

- **.NET 8** — платформа
- **Telegram.Bot** — Telegram Bot API
- **JSON-файлы** — текущее хранилище данных
- **LinqToDB + PostgreSQL + Npgsql** — заготовка для СУБД

---

## Запуск

1. Клонировать репозиторий.
2. Выполнить `dotnet run`.
3. При первом запуске ввести токен Telegram-бота (сохраняется в `config.json`).
4. Убедиться, что папка `Data/` содержит тестовые JSON-файлы (копируются в output автоматически).
